### v1.2.0 — 2026-09-28 (cleanup amendment; configuration authority, no environment file, one input per field)

- **Rationale**: the product owner asked for a cleanup review after this feature's gate — *"with the settings page, we no longer need a `.env` file and the OpenChamber config doesn't need the settings/account setup."* This document is where the first half of that ask lands, because it is the document that owns the configuration surface: it specifies ten fields, their bounds, their take-effect classes, and their single write path, yet it never stated **where configuration authority begins and ends** — the bootstrap environment's role, the `.env` file's absence, and the rule that a field has one input were all true of the design and written down nowhere. Meanwhile the repository ships a `.env.example` documenting five `MECHA_TURK_*` knobs that **no code reads** (`service/env.ts` is only `port` + `token`, host-provided) and a commented credential line, so the one file an operator might configure through is the one file with nothing behind it. A specification that says *config.json is the surface* while its repository ships a competing template has two answers to "where do I set this?", and this feature exists precisely to give that question one.
- **Sequencing decision**: block J is allocated (`FR-090`–`FR-092`) — the reserved-blocks convention exists for exactly this, a review finding taking its own group instead of being squeezed into an unrelated one. The **card half** of the cleanup is 002's (002 FR-041, in 002's `### v1.6.0` entry) and the **panel half** is 005's (005 FR-006, in 005's `### v1.2.0` entry); this document states the authority both of those point at, and is amended by bump rather than in place because three new normative requirements are added — unlike 002's v1.5.0 in-place edit, there is no way to read block J without a version.
- **Principles reviewed, unchanged in substance**: Principle V (minimal, self-hosted) is the principle a dead template fails: infrastructure that no reliability or security need justifies — a configuration file nothing reads — is exactly what that principle forbids. Principle II (safe autonomy) is served by keeping the bootstrap pair **fail-closed** (missing or malformed refuses to start, naming the variable, never the value) and by never letting an environment value silently override an operator's stored configuration. Principle IV (human-visible auditability) is the reason one layer answers "what is the service configured to do" — `config.json`, whose change already leaves a `config.changed` row. Principle VI (specification and verification before implementation) is why each removal carries a scan-able acceptance criterion. No principle is weakened, and **no gate answer is revisited**: FR-084's ten-field contract, `## Deferred`, and all four gate answers stand verbatim.
