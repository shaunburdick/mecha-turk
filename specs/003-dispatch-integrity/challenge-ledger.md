### NEW findings

**NEW-1 (material) — the v1 → v2 reading rule does not cover three of the four new record members, and the fail-closed reader makes that total.**
FR-024 (`spec.md:240`) says "a stored `dispatch-attempts-1` document MUST still read … an upgrade MUST NOT cost an operator an unacknowledged attempt". The shape it must read into requires `"projectId": "…"`, `"worktreeOption": "…"` and `"settledAt": "RFC3339" | null` (`contracts/reconciliation.md:15-19`); `data-model.md:172` lists the same members and marks only `authorizedAt` and `settledAt` nullable; T-046's v1 test asserts only "`authorizedAt` null on every row". A v1 row carries none of `projectId`, `worktreeOption` or `settledAt`, and `readDispatchRecord` refuses the **whole** document when any row is unusable (`src/dispatch-record.ts:388-408`), so `loadDispatchRecord` returns `ok: false` and every unacknowledged attempt is lost — the exact cost FR-024 forbids. Following the shape produces that refusal; following the FR requires inventing a nullability no clause states, and no test distinguishes the two. This is a fail-closed posture (constitution II) meeting an unstated migration rule, and the choice is currently invisible.
*Smallest fix:* declare `projectId: string | null` and `worktreeOption: string | null` (null on a v1 row, with the warning saying they are unavailable), have contract §1 rule 8 state that `settledAt` and those two read `null` on a v1 row, and add that to T-046's v1 sentence.

**CLOSED (round 3).** Fixed on the substance the finding names — nullability stated, not inferred. `projectId: string | null` and `worktreeOption: string | null` join `settledAt: string | null` in FR-024 (`spec.md:239`), `data-model.md:172`, and contract §1's shape and rule 8 (`reconciliation.md:15,24,48`). All three state that a v2 write from the intent writer always carries the run's project and worktree option, so `null` in either means only "read from a v1 document", `null` in `settledAt` means only "not settled", and no member's `null` refuses the row. T-046 (`tasks.md:219`) now requires the stored-v1 test to read back `authorizedAt`, `projectId`, `worktreeOption` and `settledAt` null on every row, with none of those nulls refusing the document. Two deliberate non-edits: AC-134 already requires "every unacknowledged attempt intact", which is the behaviour, and a fifth copy of the null list is what the cut list exists to remove; FR-025's warning needed no clause because a v1 row always carries a resolved outcome, so it is re-reported and never surfaced, and its null project and worktree option never reach the warning.

**NEW-2 (material) — FR-045's evictability clause is unverified, and `data-model.md` still states the opposite rule.**
FR-045 requires a settled record to be "as evictable as an acknowledged one, so a settlement can never pin the document against its attempt cap (NFR-107)", and contract §1 rule 6 agrees. But `data-model.md:172` still carries "(evict oldest *acknowledged* first; never evict an unacknowledged record)" in the same cell as "a settled record is evictable as though acknowledged"; `appendAttempt` evicts the first `acknowledged` record and stops when none is (`src/dispatch-record.ts:432-448`); and no test in T-046, T-048 or contract invariants 1–12 asserts that a settled, unacknowledged record is ever the victim. An implementation that follows the existing function and the data-model sentence leaves every settled unknown record pinned forever — HOLD-2's failure returning through the clause that was meant to close it — and the offline suite would stay green, which fails constitution VI for the one observable effect of `settledAt`.
*Smallest fix:* change the data-model parenthetical to "never evict an unacknowledged, unsettled one"; make the victim predicate `acknowledged || settledAt !== null`; add "a settled unknown record is evicted before any acknowledged-or-unsettled record" to T-046's test list (the function is already pure and testable).

**CLOSED (round 3).** The rule is one sentence, stated identically in FR-045 (`spec.md:264`), `data-model.md:172` and contract §1 rule 6 (`reconciliation.md:46`): the cap evicts the oldest record that is **acknowledged or settled**, and never evicts a record that is both unacknowledged and unsettled. `data-model.md`'s contradictory "(evict oldest acknowledged first; never evict an unacknowledged record)" is gone, along with its separate "evictable as though acknowledged" clause and contract §3's duplicate parenthetical — the rule now lives in one place per artifact rather than three. T-046 (`tasks.md:219`) carries the assertion: the cap evicts a settled unacknowledged record (an eligible victim) and never a record that is both unacknowledged and unsettled.

Nothing else rises to material: the deferred Actions B/C/D are recorded in `## Out of Scope` rather than implemented; the warning's "row could not be read" copy in the load race is the stated degradation, not a silent skip; and the acknowledge-carries-outcome repair is redundant with FR-045's `dispatch.result` evidence but is a ruled decision implemented as stated.

The artifact is unambiguous and the code disagrees with it in three places at once. The test's name says *evicted*; nothing was evicted. An evicted record leaves **no** entry at `(correlationId, attempt)` and appending is correct there. The case actually exercised is **supersession**: a record at the same `(correlationId, attempt)` under a different lease. 3.
