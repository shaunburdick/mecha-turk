### v1.2.0 — 2026-10-05 (the prose budget's unit: prose lines → prose words)

- **Rationale**: FR-049's *"a move, not an expansion"* had to be falsifiable, and a budget is what makes it so — which is why AC-016 measures prose at all. **The unit it measured in was wrong**, and it was wrong in a way that punished this specification's own required format. AC-016 at v1.0.0 named no unit; the enforcing test (`tests/prose-budget.test.ts`) resolved it to **prose lines**, and that resolution reported the shipped state as *met on words, missed by sixteen lines* (462 against the pre-feature 446), with the sixteen recorded as tracked debt. The measurements, taken with the one markup-stripping rule the test already used, are: pre-feature budget `README.md` + operator walkthrough at `d2d3f40`, **446 lines / 5,770 words**; shipped spend, the five site pages plus the reduced README, **462 lines / 5,040 words**. So the documentation **shrank by 730 words (13%)** while growing sixteen lines (3.6%). **The sixteen are structural, not a wrap artefact** — the site's content is cut into more, shorter units (headings, list items, definition terms, table cells), giving **10.9 words/line against the documents' 12.9**, and this was **measured rather than assumed**: re-flowing the entire site at the pre-feature 80 columns measures **450** lines, still over. A budget that punishes the format FR-001, FR-015, and FR-028/FR-029 require, while measuring template structure rather than reader burden, **is measuring the wrong thing**. Words keep the claim falsifiable and cost the format nothing.
- **Requirements changed, one by one** — **no requirement id was renumbered, added to, or dropped**, and the counts v1.0.0 recorded (76 FRs → 77 at v1.1.0, 9 NFRs, 10 SCs, 31 ACs) are unchanged:
  - **AC-016 — re-cut in place, id unchanged.** *Was:* *"Measured documentation prose — site content plus README — does not exceed the README plus the operator walkthrough as measured before this feature, excluding per-page navigation and footer furniture, with the measurement command and both figures recorded in the pull request."* *Now:* the same obligation with **prose words** named as the unit, plus an explicit clause that the prose **line** count of the same set is measured and recorded beside the words but is **not an enforced ceiling**, and why — a prose line is a unit of layout rather than of reader burden, and the specified format is cut into more, shorter units than the paragraphs it replaced. **The `excluding per-page navigation and footer furniture` qualifier is retained verbatim**: it still describes the same exclusion, and it remains satisfied by construction rather than by a filter. **Not weakened** — the ceiling did not move. It is the **pre-feature figure itself**, enforced at **5,770 words**, and the shipped state meets it with **730 words of room**. What was removed is a *second, wrong* bound on a unit that is not burden.
  - **NFR-006 — re-cut in place, id unchanged.** *Was:* *"...**Verified by**: comparing the measured prose **lines** before and after against `.project-health/baseline.json` (`allDocProseLines: 10833`), which the repository's most recent commit moved in the direction of reduction."* *Now:* the same obligation in **words**, verified by comparing the spend against **those two documents' own pre-feature word figures**, carried as **recorded constants** rather than re-derived, so the comparison needs no repository history. **The `.project-health` distinction is made explicit rather than blurred**: `allDocProseLines` is a tracked metric **of the project-health skill** over a different population — every documentation prose line in the whole repository, not these four documents' — and it is that skill's to regenerate deliberately. It is therefore **read, never pinned**, and carried into the test's failure output as the surrounding repository-wide reference. **`.project-health/baseline.json` is unchanged by this amendment**; its `_note` is the ratchet rule this feature obeys — *"Raising a value is allowed and shows up as a visible diff; that visibility is the mechanism."*
- **Ratchet preserved, on both metrics**: the word ceiling is enforced, so growth past 5,770 words **fails visibly**; admitting a legitimate increase is a **one-line diff** to a recorded constant, reviewed in the pull request. The line count stays measured, reported, and **pinned** to a recorded figure, so it cannot move unnoticed — but as a **record, not a ceiling**, which the test says in its own body. `BEFORE` remains a constant derived once from `d2d3f40` and **never re-derived at run time**, because `actions/checkout` in `verify.yml` is at default depth and a history read would pass locally and fail in the one place the gate runs. Nothing in the budget is silently satisfiable.
- **Migration impact**: **none to the product — no code changes behaviour; only the measurement changes.** No manifest key, capability, storage key, audit row, configuration field, wire schema, panel string, or service behaviour moves; no `.astro` page, `README.md`, or walkthrough text is touched by this amendment. The sole changed artefact is `tests/prose-budget.test.ts`, whose constants and assertions are re-pointed at the word figure; its prose-measurement machinery — the markup stripping, the fence rule, the furniture exclusion by construction — is **unchanged**, because what it is compared against is what was wrong. `panel/main.js` and `service/main.js` are **not** rebuilt, because no source changed. No predecessor's requirement-id set changes: 002's and 005's `FR`/`AC`/`SC`/`NFR` sets are byte-identical to the state recorded in their own `### v1.13.0` and `### v1.16.0` entries, and **no requirement in either is amended by this version**. The constitution was **not** amended — `.specify/memory/constitution.md` remains at v1.3.0. `plan.md` and `tasks.md` keep their v1.0.0 wording as dated phase records (T-035 still says *"measured against `.project-health/baseline.json`"*, which was already imprecise and which NFR-006 now states precisely); the authoritative text is **AC-016 and NFR-006 in `spec.md`**, which is where a reader of a requirement goes.
- **Approval status**: **Approved by the product owner 2026-10-05 as a requirement amendment** — this is a ruling, not a default, and it is in force for the requirement it amends. The specification as a whole remains **Draft**, submitted for product-owner approval, alongside 002 v1.13.0 and 005 v1.16.0, which are unchanged drafts of record.

### v1.0.0 — 2026-10-05 (initial specification)

- **Rationale**: GitHub issue #11 asked for a GitHub Pages homepage with a landing page explaining what the tool does and help-style documentation for install, configure, use, and debug. The specification exists because the documentation had **two homes and no owner**: `README.md` (384 lines) and `specs/002-agent-event-extension/quickstart.md` (~180 lines, of which §6 spends 94 lines on the service store) both carried install, first-run, store, and troubleshooting prose, neither was authoritative, and the drift was already visible — `README.md` §Install tells the reader the approval dialog *"asks for exactly these four things"* and names `network`, while `AGENTS.md` invariant 3 records that `network` was removed by product-owner order on 2026-09-30 and is *"no longer requested at all"*. A third surface without a synchronisation requirement attached would have made that worse, so the feature amends 002 FR-042 rather than merely adding a site (see the table above).
- **What this version specifies**: 76 functional requirements in seven blocks (site shape; landing page; the four documentation pages; fidelity and the single-source rule; entry points; build, verification, publishing; the licence), 9 non-functional requirements, 10 measurable outcomes, and 31 binary acceptance criteria.
- **The constraint that shaped it**: this is a **move**, not an expansion. 007 FR-049 requires each README section to map to exactly one site page with no substance left in both places, and NFR-006 measures documentation prose before and after against `.project-health/baseline.json` (`allDocProseLines: 10833`) so the move is falsifiable rather than asserted. The repository's most recent commit on `main` (`d2d3f40`, *"repository reduction pass — comments, tests, specs, instruction surface, lint config"*) moved that number in the direction of reduction.
- **The one conflict the feature had to resolve**: Astro 7 requires Node ≥ 22.12.0; the repository's root `package.json` declares `>=20.19.0` and, by `AGENTS.md` invariant 2, **may not** gain a `workspaces` key because it is simultaneously the npm dev package and the OpenChamber installable manifest. Raising the root floor belongs to issue #17. The resolution is a self-contained subproject with its own manifest, its own lockfile, and its own declared floor — which means **the root `npm run verify` cannot reach the site**, so the site's pull-request job becomes its only gate (FR-065, FR-069). That consequence is stated in `spec.md` → `## Clarifications` Q4 rather than discovered during implementation. Full evidence in [research.md](research.md) §2.
- **The one staleness the feature refuses to carry forward**: the `network` permission row. FR-022 requires the install page's table to be derived from the shipped manifest and to name exactly the capabilities the manifest requests (`sessions` and `prompt`, with `service` implied), and AC-008 checks the page against the manifest. Placement of the README-side correction — here or in issue #16's follow-up — is recorded as `spec.md` → `## Clarifications` Q2, with **correcting it here** as the encoded default, because this feature rewrites that paragraph regardless. *(Superseded at v1.1.0: Q2 answered — **corrected here** — and the ruling is carried by the new FR-077 rather than by FR-022 alone.)*
- **Migration impact**: none to the product. No manifest key, capability, storage key, audit row, configuration field, wire schema, or service behaviour changes. The only runtime-adjacent change is one text handle in `src/about-tab.ts`, which under `AGENTS.md` invariant 1 ends with the rebuilt `panel/main.js` committed in the same commit. The root verification command keeps its steps, its order, its timeout, and its test count. The Pages site was already enabled with `build_type: "workflow"` and has **never been published** — `https://shaunburdick.github.io/mecha-turk/` returns HTTP 404 today — so the feature's own published address is new and AC-025 measures against that 404 baseline rather than against a working site.
- **Open, not blocking**: three confirmations, each with an encoded default — the MIT copyright holder (Q1), the placement of the `network`-row correction (Q2), and whether the debug page documents the local service's HTTP surface (Q3). Each is a one-line copy change or a scope confirmation if the answer differs; none changes a requirement's shape. *(Superseded at v1.1.0: all three answered on 2026-10-05. The closing clause did not survive them — Q2's answer **did** change a requirement's shape, adding FR-077 — so this entry is left as the record of the assumption it was written under.)*
- **Approval status**: **Draft, submitted for product-owner approval.** Awaiting (a) the three confirmations above — *answered 2026-10-05, see `### v1.1.0`* — and (b) approval of v1.0.0 itself, which is expected in the same package as the two predecessor amendments it carries. The constitution was **not** amended — `.specify/memory/constitution.md` remains at v1.3.0, with the reasoning recorded in `spec.md` → `## Clarifications` Q4 and `research.md` R-8.
